# H0.5 — Platform Architecture Foundation

**Status:** COMPLETE (2026-08-19)
**Type:** Architecture checkpoint. **No feature implementation.**

## Objective

Specify the architecture of everything that will sit **above and around** the kernel, so that
M1–M4 cannot accidentally make assumptions that render the intended runtime, SDK, application
model, graphics, media, storage, compatibility, security, cloud and product architecture
difficult or impossible.

## Why it exists between M0 and M1

M0 proved the kernel boots. M1–M4 make decisions — memory model, syscall surface, driver
boundaries, virtualization placement — that are **cheap now and very expensive later**.

[ADR-0004](../adr/ADR-0004-kernel-object-model.md) established this discipline for the kernel
object model. H0.5 extends it to the rest of the platform. The concrete items it protects are
listed in [`DEPENDENCY-GRAPH.md`](../architecture/DEPENDENCY-GRAPH.md) under "what M1–M4 must
not foreclose".

## Explicitly out of scope

**No feature implementation.** No libc, runtime, compositor, package manager, Files, Shield,
Broadcast or compatibility layer was built. **M1 was not started.**

The only code change was a correctness fix keeping a documented invariant true — see below.

## Success criterion

For any named component — Files, compiler, libc, GPU driver, Browser, Shield, Broadcast,
Store, Wine, Mobile shell — the repository can answer: where it belongs, what it depends on,
what depends on it, whether it is privileged, which security boundary owns it, build or reuse,
which API layer it uses, when it can be implemented, and what must be decided first.

Entry points: [`PLATFORM-CAPABILITY-MAP.md`](../architecture/PLATFORM-CAPABILITY-MAP.md) and
[`DEPENDENCY-GRAPH.md`](../architecture/DEPENDENCY-GRAPH.md).

## Code change

One fix, permitted as "required to keep M0 correct": the committed `.cargo/config.toml`
asserted the non-PIE kernel invariant was enforced by `core/kernel/build.rs`, but the link
argument had never been committed — a bare `cargo build` produced `ET_DYN`. Not a safety hole
(the loader's `e_type` check made it loud, which is why CI stayed green), but a
documentation/reality mismatch. Fixed in `ed5621b`.
