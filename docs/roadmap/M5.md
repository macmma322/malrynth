# M5 — Storage, System Services and Updates

**Status:** NOT STARTED. **Depends on:** M4.

## Objective
Make Malrynth self-hosting as a text-mode system: filesystems, a program loader, a network
stack, packages, transactional updates, and offline recovery.

## Scope
VFS and filesystem services in user space; at least one real filesystem; the ELF program
loader as a service; a POSIX/libc subset sufficient to port existing software; a Rust `std`
port; TCP/IP; a terminal and shell; the package format and manager; **transactional,
rollbackable updates**; offline recovery; image signing and Secure Boot support.

## Explicitly out of scope
Graphics, GUI applications, full POSIX conformance, MalrynthFS as production storage —
MalrynthFS remains R&D and must not hold data anyone values.

## Exit criteria
Malrynth boots from a real filesystem on real hardware; packages install and remove; an
update applies transactionally and rolls back after an induced failure; recovery works with
no network; the kernel image is signature-verified at boot.

## Gates
**Performance:** filesystem metadata and throughput; process creation; update apply/rollback
duration; idle CPU and RAM become tracked budgets.
**Security:** T2 (malicious files), T8 (filesystem corruption), T12 (signing key) and T13
(rollback) addressed. Anti-rollback must be reconciled with Constitution §10's rollback
guarantee — a genuine tension requiring an ADR.

## Documentation
Filesystem and package specifications; update/recovery architecture; signing key management;
MalrynthFS design record; threat-model revision.
