# M2 — User Mode and Scheduling

**Status:** NOT STARTED. **Depends on:** M1.

## Objective
Run untrusted code at CPL 3 under a Malrynth scheduler, with a syscall boundary.

## Scope
Address-space and thread objects; ring-3 transition; syscall entry/exit (`syscall`/`sysret`)
with full register discipline; context switching; a scheduler (initially round-robin, with
the interface designed for later policies); user stacks and guard pages; process creation
from an in-memory image; a minimal user-space runtime with no libc.

## Explicitly out of scope
Capabilities and IPC (M3) — M2's syscall surface is deliberately minimal and temporary.
Filesystems, drivers, networking, graphics.

## Exit criteria
A user-mode program runs, makes a syscall, is preempted, resumes correctly, and cannot access
kernel memory (verified by attempting it). Multiple threads schedule across all CPUs.
`MALRYNTH_M2_USERMODE_OK`.

## Gates
**Performance:** syscall round trip and context switch measured; both become tracked budgets.
**Security:** the syscall boundary treats every argument as untrusted; no pointer is
dereferenced without validation; no TOCTOU between validation and use; no kernel memory or
uninitialised padding disclosed to user space.
