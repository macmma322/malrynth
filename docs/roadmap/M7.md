# M7 — Developer Desktop and First Applications

**Status:** NOT STARTED. **Depends on:** M6.

## Objective
A Malrynth desktop usable by a developer, and the SDK/DDK that lets others build for it.

## Scope
The desktop shell and session; the first first-party applications — Files, Settings, Search,
Monitor, Terminal, and a package UI; the Shield security baseline; the SDK and DDK with
stable, documented APIs; the developer CLI and templates; first compatibility previews.

## Explicitly out of scope
The full application catalogue in `docs/application-map.md`, gaming, Broadcast, cloud
account and sync, organisations/MDM, Mobile, Console.

## Exit criteria
Malrynth is usable as a daily development machine by its own developers — the only honest
test of a desktop. A third-party developer can build, package and install an application
using published SDK documentation alone.

## Gates
**Performance:** application cold/warm start; Files navigation on a large directory; idle CPU
and RAM under a full desktop session; Shield overhead measured as a delta.
**Security:** first-party applications hold no capability unavailable to a third party
(Constitution §7) — verified, not asserted; the desktop's capability surface is reviewed
end to end.

## Documentation
SDK and DDK documentation; application development guide; API stability policy, with the
first interfaces promoted to LOCKED and thereby to a compatibility commitment.
**ADR-0001 split criteria are re-evaluated for `sdk/` and `apps/`**, which by this point may
genuinely satisfy the independent-release and multi-consumer criteria.
