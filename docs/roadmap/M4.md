# M4 — Devices and Drivers

**Status:** NOT STARTED. **Depends on:** M3.

## Objective
Enumerate real hardware and run drivers as unprivileged, capability-confined user-space
programs.

## Scope
Full ACPI parsing; PCIe enumeration and configuration; IOMMU (Intel VT-d, AMD-Vi) setup and
DMA confinement; MMIO and interrupt capabilities; device manager and driver manager; the
driver framework and DDK shape; first drivers — NVMe, xHCI, HID, an Ethernet MAC.

## Explicitly out of scope
Filesystems (M5), networking protocols above the MAC (M5), GPU (M6). Linux driver
compatibility is not in scope and may never be.

## Exit criteria
Drivers run in user space; a driver crash is contained and the driver restarts; DMA is
IOMMU-confined and a driver cannot reach memory it was not granted (verified adversarially);
storage and input work on at least one physical machine, not only QEMU.

## Gates
**Performance:** interrupt-to-handler latency; storage throughput and latency; the overhead of
user-space drivers versus an in-kernel baseline, measured and disclosed.
**Security:** malicious-device and malicious-driver threats (T4, T5, T6) move from PLANNED to
mitigated-with-tests; behaviour without an IOMMU is documented rather than implied.

## Documentation
Driver model promoted from PROPOSED; DDK specification; IOMMU policy ADR; threat-model revision.
